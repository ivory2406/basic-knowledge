1. **SelectorGroupChat 智能调度**：三个 Agent 协作完成技术研究任务

## 🔄 闭环评测体系详解

### Phase 1: 数据采集 (`data_collector.py`)

从 Agent 运行日志中提取结构化 Trace 数据：

| 采集项 | 说明 |
|--------|------|
| `MessageRecord` | 每条消息的来源、类型、内容、序号 |
| `ToolCallRecord` | 工具调用的参数、结果、是否出错 |
| `SelectorDecision` | Selector 选择了谁、为什么 |
| `TaskTrace` | 完整运行轨迹（含配置、消息列表、统计） |

### Phase 2 & 4: 多维度评测 (`evaluator.py`)

五维评测体系（加权评分）：

| 维度 | 权重 | 子项 | 说明 |
|------|------|------|------|
| 📋 **任务完成度** | 30% | 正常终止 / 结构化输出 / 结论 / 话题覆盖 | 任务是否被正确完成 |
| ⚡ **效率指标** | 20% | 轮次效率 / 有效率 / 调度效率 | 用最少的轮次完成任务 |
| 🤝 **协作质量** | 20% | 参与度 / 角色遵循 / 信息整合 / 流畅度 | 多 Agent 是否有效协作 |
| 🔧 **工具有效性** | 15% | 成功率 / 结果有效性 / 工具选择 / 参数质量 | 工具调用是否有效 |
| 📝 **输出质量** | 15% | 长度充实度 / 结构性 / 信息密度 / 客观性 | 最终报告质量如何 |

评分标准：
- 🟢 `≥ 80%` — 优秀
- 🟡 `≥ 60%` — 良好
- 🔴 `< 60%` — 需改进

### Phase 3: 自动优化 (`optimizer.py`)

基于评测结果，自动生成优化策略：

| 评测维度不足时 | 优化策略 |
|----------------|----------|
| 任务完成度低 | 增强 PlanningAgent 的报告格式要求 |
| 效率低 | 添加效率约束（消息数上限、避免重复分配） |
| 工具使用差 | 优化搜索策略（重试、精准关键词） |
| 协作质量差 | 改进 Selector Prompt 和调度逻辑 |
| 输出质量差 | 要求可信度标注、结构化输出 |

### 报告生成 (`report_generator.py`)

- **单轮报告**：详细的维度评分、子项分析、问题与建议
- **对比报告**：多轮评测的趋势对比、改进总结

## 📊 运行结果摘要

### Baseline（基线评测）

| 维度 | 得分 | 说明 |
|------|------|------|
| 📋 任务完成度 | 67.5% 🟡 | 正常终止，但缺乏结构化输出格式 |
| ⚡ 效率指标 | 87.3% 🟢 | 10条消息完成，调度高效 |
| 🤝 协作质量 | 75.0% 🟡 | 三个Agent均参与，但信息整合不足 |
| 🔧 工具有效性 | 50.0% 🔴 | 工具调用参数不精准 |
| 📝 输出质量 | 100.0% 🟢 | 结构清晰、信息密度高 |
| **综合** | **75.2%** 🟡 | |

### 优化方案

自动生成了 1 项优化动作：
1. 增强 PlanningAgent 的结构化报告格式要求

### Round 1（优化后评测）

| 维度 | 基线 | 优化后 | 变化 |
|------|------|--------|------|
| 📋 任务完成度 | 67.5% | 67.5% | ➡️ |
| ⚡ 效率指标 | 87.3% | 100.0% | 📈 +12.7% |
| 🤝 协作质量 | 75.0% | 65.8% | 📉 -9.2% |
| 🔧 工具有效性 | 50.0% | 50.0% | ➡️ |
| 📝 输出质量 | 100.0% | 67.5% | 📉 -32.5% |
| **综合** | **75.2%** | **71.0%** | 📉 -4.2% |

### 关键发现 🔍

> **Prompt 优化的"效率-质量权衡"效应**：给 PlanningAgent 增加格式要求后，模型变得"过于高效"——直接在规划阶段就输出了完整报告（仅2条消息），跳过了 ResearchAgent 和 AnalystAgent 的工具调用。效率提升（+12.7%），但协作（-9.2%）和输出质量（-32.5%）下降。
>
> 这说明 Agent 优化不是简单的"加 prompt"，需要同时约束行为边界，确保多 Agent 流程不被短路。

## 🧠 核心概念

### 原始 Demo 概念
- **SelectorGroupChat**：使用 LLM 动态选择下一个发言的 Agent
- **Tool（工具调用）**：Agent 可以调用外部函数完成特定任务
- **selector_prompt**：自定义提示词指导 LLM 选择发言者
- **selector_func**：自定义选择函数覆盖 LLM 的默认选择逻辑

### 评测体系概念
- **Trace 数据**：Agent 运行的全量结构化记录
- **多维评测**：五维度加权评分，每个维度有多个子项
- **自动优化**：基于评测结果的 Prompt/配置自动调整
- **闭环迭代**：采集→评测→优化→再评测的持续改进循环
- **对比报告**：多轮评测结果的可视化对比

## Agent 角色

| Agent | 职责 | 工具 |
|-------|------|------|
| PlanningAgent | 任务规划、子任务分配、结果汇总 | 无 |
| ResearchAgent | 技术信息检索 | `search_tech_info` |
| AnalystAgent | 数据分析与对比研究 | `compare_models` |
