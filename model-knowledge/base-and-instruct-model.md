# Base 模型和非 Base 模型的区别

Base 模型可以理解成“刚学完大量文本、还没被训练成聊天助手的底座模型”。非 Base 模型通常是在 Base 模型基础上继续做后训练，变成更会听指令、更适合直接使用的模型。

---

## 1. 一句话理解

```text
Base 模型 = 预训练后的底座模型
非 Base 模型 = Base 模型 + 后训练后的应用型模型
```

更直观地说：

- **Base 模型**：更像“语言续写器”，擅长根据前文继续生成文本。
- **非 Base 模型**：更像“助手产品”，擅长理解用户指令并完成任务。

---

## 2. 常见模型类型

| 类型 | 训练状态 | 特点 | 适合做什么 |
|---|---|---|---|
| Base 模型 | 大规模预训练完成 | 会续写文本，但不一定听指令 | 继续训练、研究、领域微调底座 |
| Instruct 模型 | Base + 指令微调 | 更会按照用户要求回答 | 问答、任务执行、API 应用 |
| Chat 模型 | Base + 对话后训练 | 更像助手，懂多轮对话格式 | 聊天机器人、Agent |
| Reasoning 模型 | Base + 推理强化训练 | 更擅长复杂推理 | 数学、代码、规划 |
| Coder 模型 | Base + 代码数据或代码后训练 | 更擅长代码 | 编程、代码补全、代码审查 |

非 Base 模型不是一个固定类别，而是泛指那些经过后训练、面向具体使用方式优化过的模型。

---

## 3. 训练流程

大模型通常先经过大规模预训练，得到 Base 模型，然后再做各种后训练。

```text
大规模预训练
    ↓
Base 模型
    ↓
指令微调 SFT
    ↓
Instruct / Chat 模型
    ↓
偏好优化 / 强化学习 / 推理训练
    ↓
更强的 Chat / Reasoning / Coder 模型
```

### 3.1 预训练阶段

预训练阶段的目标是让模型学习语言规律、知识、代码模式和世界知识。

训练方式通常是：

```text
给定前面的 token，预测下一个 token
```

例如：

```text
输入：北京是中国的
目标：首都
```

预训练完成后得到的就是 Base 模型。

### 3.2 后训练阶段

后训练的目标是让模型更适合真实使用场景，例如：

- 理解用户指令。
- 按格式回答问题。
- 拒绝危险请求。
- 保持多轮对话上下文。
- 更擅长推理、代码、工具调用。
- 输出更符合人类偏好的答案。

常见后训练方式包括：

- **SFT（Supervised Fine-Tuning）**：用人工或合成的指令-回答数据训练模型。
- **RLHF / RLAIF**：用人类或 AI 偏好信号优化回答质量。
- **DPO / PPO / GRPO**：不同形式的偏好优化或强化学习方法。
- **Domain Fine-tuning**：针对代码、数学、医疗、法律等领域继续训练。

## 4. 行为差异示例

假设输入：

```text
请解释什么是 KV Cache
```

### 4.1 Base 模型可能的输出

Base 模型可能会把这句话当成一段文本的开头，然后继续续写：

```text
请解释什么是 KV Cache。KV Cache 是一种在 Transformer 中...
```

它不一定稳定地理解“请解释”是一个用户指令，有时会继续补全文本，有时会输出文章片段，有时格式不稳定。

### 4.2 Instruct / Chat 模型可能的输出

Instruct 或 Chat 模型更可能直接回答：

```text
KV Cache 是 Transformer 推理时缓存历史 token 的 Key/Value 的机制，用来避免每生成一个新 token 都重新计算全部上下文。
```

因为它经过了指令微调和对话后训练，更知道用户是在请求它完成一个解释任务。

---

## 5. 为什么还需要 Base 模型

既然非 Base 模型更好用，为什么还要发布 Base 模型？

### 5.1 适合继续训练

Base 模型没有被强烈塑造成某种助手风格，更适合作为二次训练的起点。

例如：

- 做行业模型。
- 做代码模型。
- 做数学推理模型。
- 做企业内部知识模型。
- 做特定语言或领域的继续预训练。

### 5.2 适合研究模型原始能力

Base 模型更接近预训练得到的原始状态，方便研究：

- 语言建模能力。
- 知识存储方式。
- 模型结构效果。
- scaling law。
- 不同后训练方法带来的变化。

### 5.3 避免后训练偏置

Chat 模型会带有后训练产生的风格和限制，例如：

- 回答更像助手。
- 更倾向安全拒答。
- 更喜欢结构化输出。
- 可能过度解释。

如果要训练一个完全不同风格的模型，从 Base 开始通常更干净。

---

## 6. 什么时候选 Base，什么时候选非 Base

| 目标 | 推荐 |
|---|---|
| 直接聊天问答 | Chat / Instruct |
| 构建普通 AI 助手 | Chat / Instruct |
| 做 Agent 和工具调用 | Chat / Instruct / Reasoning |
| 写代码、改代码 | Coder / Reasoning / Chat |
| 做数学、逻辑推理 | Reasoning |
| 做领域继续训练 | Base |
| 做 SFT 或 LoRA 微调 | Base 或 Instruct，取决于任务 |
| 研究模型原始能力 | Base |
| 做文本续写实验 | Base |

---

## 7. 微调时怎么选

### 7.1 选择 Base 的情况

适合：

- 你有大量领域语料。
- 想训练一个新风格或新能力模型。
- 不希望继承太多助手对话风格。
- 要做继续预训练或深度领域适配。

风险：

- 需要更多训练数据。
- 需要自己补指令能力。
- 输出安全性和可控性较弱。

### 7.2 选择 Instruct / Chat 的情况

适合：

- 你只是想让模型更懂某类指令。
- 想快速做业务问答或工具调用。
- 数据量不大。
- 希望保留模型原有的助手能力。

风险：

- 可能继承原模型的回答风格。
- 可能和原有安全策略、对话模板耦合。
- 深度领域改造空间可能小于 Base。

---

## 8. 常见误区

### 8.1 Base 模型不是“更弱模型”

Base 模型不是简单意义上的弱，而是没有被调成助手。它可能有很强的知识和语言能力，但不一定以用户期待的方式输出。

### 8.2 Chat 模型不是只多了一个提示词

Chat 模型通常不只是套了 system prompt，而是经过了指令微调、偏好优化、安全对齐等后训练。

### 8.3 Instruct 和 Chat 不完全一样

两者经常混用，但可以粗略区分：

- **Instruct** 更强调单轮指令跟随。
- **Chat** 更强调多轮对话格式和助手行为。

实际项目中，具体差异要看模型发布方的定义。

### 8.4 非 Base 模型也可以继续微调

很多业务微调会直接基于 Instruct 或 Chat 模型做 LoRA，因为这样更省数据，效果也更快。但如果目标是深度改变模型能力或风格，Base 往往更适合。

---

## 9. 总结

最简单的理解是：

```text
Base 模型是原材料 / 底座。
非 Base 模型是经过后训练、面向具体使用方式调好的产品形态。
```

如果你要直接用模型完成任务，优先选 Instruct / Chat / Reasoning / Coder。  
如果你要继续训练一个自己的模型，或者研究模型原始能力，Base 模型更合适。
